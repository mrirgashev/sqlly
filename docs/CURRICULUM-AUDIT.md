# Curriculum inventory and review notes

The installed English and Russian course packs each contain **34 topics, 102 concept lessons, and 516 exercises**. They contain original explanations, prompts, datasets, hints, and solutions and do not reproduce Stepik lesson text. Every concept retains eleven educational sections, presented as one introduction, five or six practice steps, and a recap. A flat topic opens the combined numbered sequence of its three related concepts.

## Assessment policy

Query answers are executed, rather than parsed or compared as SQL strings. Result checks preserve duplicates and NULL values. An exercise declares whether output names and row order matter. Exact numeric comparison does not depend on decimal display scale. Every result exercise is checked against an independently executed reference on equivalent fixture data.

One hundred thirty-eight exercises include dedicated state queries. Their catalog snapshot checks the current schema's column names/order/types, nullability, defaults, identity and generated settings, normalized constraint definitions, index access methods/keys/predicates, row-security settings/policies, and partition keys/bounds. Constraint and index names are excluded from that generic snapshot; an exercise may explicitly require a named index for its dedicated query. Ordinary alternate names for equivalent primary/foreign/check constraints are accepted. Schema checking is conservative structural equivalence; it is not a theorem prover for arbitrarily rewritten CHECK expressions.

A state check proves the resulting state rather than requiring particular SQL text. For example, a transaction exercise can accept a different valid transaction that produces the same state. Maintenance tasks inspect observable catalog effects; they cannot prove the precise maintenance command used. EXPLAIN exercises use the bundled version and controlled fixtures; production query plans can differ with version, statistics, data size, and settings. Written explanations are explicitly self-assessed and are not claimed to be automatically understood by an English-language grader.

The generator integrates actual PostgreSQL 18.6 result previews for all 102 lessons. Previews show up to eight rows, preserving NULLs, and record the total row count. English source lives in `scripts/generate-curriculum.py` and the additional practice JSON files; `scripts/expected-previews.json` contains generated observations. The Russian adaptation is generated by `scripts/localize-curriculum.py` from authored resources. It preserves executable SQL, grading rules, fixtures and progress IDs; its parity audit is in `docs/verification/localization-content-audit.json`. Only instructional full-line starter comments are translated. See [localization authoring](LOCALIZATION-CONTENT.md). Python is used only by contributors, never by the released app.

## Scope and depth

The course spans relational foundations; selecting/filtering; missing values and patterns; aggregation/grouping; joins/cardinality; subqueries/CTEs/set operations; writes/transactions/upserts; scalar types, time, arrays and JSONB; constraints/schema design/migrations; windows; views/materialized views; functions/procedures/PLpgSQL; triggers/full-text search; five index families; plans/statistics/maintenance; concurrency/security; operations; recursion; ranges/partitioning/generated columns; gaps-and-islands and relational division; and commerce, inventory, hospitality, finance and analytics projects.

The app's one-query-at-a-time workspace does **not** provide competing live sessions for lock waits, deadlocks, isolation anomalies, or pool behavior. Lessons explain those behaviors and run safe single-session syntax exercises. Backup/restore CLI tools, replica provisioning, failover, and production incident response are taught as concepts and checks. They are not advertised as executable multi-server labs. Role administration and unrestricted extensions are intentionally unavailable to the learner role. Synthetic datasets teach semantics; they cannot establish production performance claims.

The 102 lessons are a broad progressive course, not a claim that every PostgreSQL feature or every professional operational situation has been exhausted. Future contributions should add more independent fixtures, richer concurrency labs with explicit safe orchestration, deeper operational projects, accessible diagrams, and peer-reviewed explanations.

## English and Russian resources

The English and Russian packs preserve the same stable lesson/exercise IDs, SQL fixtures, starter/reference code, validation queries, and assessment policies. Russian prose is bundled at `curriculum-ru.json`; SQL keywords, identifiers, and sample-data values retain their executable form. The authoring tables and additional bilingual exercises live in `scripts/ru-lessons.tsv`, `scripts/ru-exercises.tsv`, `scripts/extra-foundation-exercises.json`, and `scripts/extra-advanced-exercises.json`. See the localization and reference-validation evidence in [VERIFICATION.md](VERIFICATION.md).

Seven tasks explicitly check their immediate submitted output as well as committed state. This includes requested INSERT/UPDATE RETURNING tables and a sequence whose creation, step, last value, and returned nextval columns all matter. The statement is executed only once in each candidate/reference database; output checking does not repeat the mutation. JSONB state numbers are normalized with exact arbitrary-precision decimal rules, while JSON strings and array order stay distinct.
